# Agent Control Plane Prod Risk Register

Scope: prod-readiness work for the internal agent management plane where an action could affect currently running agents or supporting services.

Source context:

- Design: `docs/agents/agent-control-plane.md`
- Current source surface: `src/agents/control/agent-control.ts`
- Current tests: `src/agents/control/agent-control.test.ts`

## Operating Rule

No live runtime mutation is allowed until the relevant risk-register item is approved for the exact target, command/change, timing window, operator, and rollback path. This includes Docker, Swarm, gateway/router config, service restarts, registry databases, live agent workspaces, manager-to-agent message sends, cron/watchers, secrets/BWS permission changes, rollback commands, and cleanup jobs.

Approval must be explicit, item-specific, and recorded with evidence before execution. Source-only code, tests, docs, offline fixtures, and image builds that are not deployed remain safe prep work.

## Default Decisions

- Live mutation default: `Hold pending approval`.
- Read-only inspection default: `Allowed` when it does not query secret values or live production data beyond ordinary status metadata.
- Source-only prep default: `Allowed`.
- Ambiguous action default: `Stop and prepare an approval packet`.

## Safe Prep Without Approval

These items can proceed without approval because they do not mutate live runtimes, authoritative production data, external systems, or secrets:

- Source-only modules under `src/agents/control/` that preserve the safe operation contract (`list`, `readStatus`, `sendMessage`, `readManagedFile`, `requestManagedFileUpdate`).
- Unit tests and contract tests using local/offline fixtures.
- Documentation updates, approval packets, rollout plans, and this risk register.
- Offline registry fixtures with synthetic agent records and no production DB writes.
- Local image build or package build that is not pushed, deployed, tagged as production, or wired into live services.
- Static config examples that are not copied into live gateway, Swarm, Docker, cron, watcher, DB, or secret manager state.

## Minimum Approval Packet For Held Items

Each held item needs:

- Intended action and matching risk-register ID.
- Exact target agents/services/routes/files/DBs/jobs/permissions.
- Exact command, config diff, migration, message body, or change plan.
- Expected effect and interruption window.
- Detection and success evidence.
- Rollback or recovery path.
- Risk if wrong.
- Explicit approval wording.

## Prod-Test Readiness Gate

Before prod testing starts, confirm:

- Every planned live mutation maps to one register item above.
- Every mapped item has explicit approval or is removed from the test plan.
- No test depends on direct live workspace writes; managed file updates remain pending-review plans until separately approved.
- No test writes live task-ledger, dashboard, alert-linked task, or operator-visible
  status rows unless `ACP-R19` is explicitly approved; shadow evidence uses a
  local fixture or clearly non-actionable shadow namespace.
- No test requires secret value disclosure or command-line secret handling.
- Employee/subagent initiated messages to Artemis or Fiona remain denied unless
  the source is explicitly present in the approved `upchainCommunication`
  allowlist.
- Gateway/router, service, DB, Swarm, cron/watch, and cleanup rollbacks are documented before the first live change.
